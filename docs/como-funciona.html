Como funciona o Hub

Um lugar só, com uma senha só, onde cada pessoa vê exatamente as ferramentas que precisa. Sem caô.

Figura 1

Uma porta, várias prateleiras

Pense numa despensa organizada: todo mundo entra pela mesma porta, mas cada um enxerga só as prateleiras que lhe cabem.

Página internaUma tela feita dentro do Hub, pelo nosso time. Ex.: relatório de royalties.
Link externoAbre outro site em nova aba. Ex.: o painel de TV das lojas.
EmbutidoMostra outro site dentro de um quadro do Hub. Ex.: uma planilha publicada.
Figura 2

Por dentro: vitrine, cérebro e arquivo

O Hub são três peças que conversam entre si. Cada uma custa quase nada e cresce sozinha se a rede crescer.

VitrineÉ o site. Hospedado na AWS (Amplify). Quando o time salva código novo no GitHub, o site atualiza sozinho em uns 3 minutos.
CérebroUma função na nuvem que só "acorda" quando alguém usa o Hub. Confere a senha, decide o que a pessoa pode ver, grava tudo que importa.
ArquivoBanco de dados Postgres, gratuito no Supabase. Guarda usuários, módulos e permissões. Se um dia mudarmos de fornecedor, é copiar e colar.

Quem vê o quê

O administrador marca, para cada implementação, quais perfis podem ver. Diretoria e administradores veem tudo. Dá para abrir exceção para uma pessoa específica.

PerfilQuemVê
AdministradorTI e estagiário de processosTudo. E gerencia usuários e implementações.
DiretoriaDono e CEOTodas as implementações ativas.
EscritórioEquipe administrativaO que for liberado para o escritório.
FranqueadoDonos de franquiaO que for liberado para franqueados.
Fábrica / LogísticaEquipe da fábricaO que for liberado para a fábrica.
E a senha? O administrador cria o usuário com uma senha temporária e passa pessoalmente ou por WhatsApp. Na primeira entrada, a pessoa escolhe uma senha só dela. Esqueceu? Pede ao administrador, que gera outra. Ninguém, nem o administrador, consegue ler a senha de alguém: ela é guardada embaralhada.
Figura 4

Como uma implementação nova entra

Cinco passos. Os dois primeiros são de quem programa; o quarto acontece sozinho; o último é um clique no painel do administrador.

  1. FazerCopiar a pasta de exemplo (exemplo-boas-vindas) com um nome novo e escrever a tela.
  2. RegistrarAcrescentar uma linha no arquivo registry.ts dizendo “esse nome abre essa pasta”.
  3. EnviarAbrir um pull request no GitHub. O robô roda os testes; alguém do time revisa e aprova.
  4. PublicarSozinho. O Amplify atualiza o site e o GitHub Actions atualiza o cérebro. Ninguém digita comando nenhum.
  5. LiberarNo Hub, em Implementações, o administrador escolhe o nome, um ícone, uma categoria e marca os perfis. Pronto.
Regra de ouro: o cadastro (nome, ícone, quem vê) fica no banco, feito pelo administrador. O código fica no repositório. O nome curto (slug) é a cola entre os dois.
Figura 5

Quanto custa e como cresce

Quase nada. Tudo roda em planos gratuitos ou por uso, e nenhuma peça precisa de servidor ligado 24 horas.

E se a rede dobrar de tamanho?

Nada muda. A vitrine e o cérebro escalam sozinhos conforme o uso. O primeiro limite prático é o espaço do banco gratuito (500 MB), muito acima do que usuários, permissões e auditoria ocupam.

E se quisermos trocar o banco?

Copiamos os dados para o novo lugar e trocamos uma linha de configuração. O código não muda, porque só o cérebro fala com o banco e ele fala em SQL padrão.

E se alguém sair da empresa?

O administrador desativa o usuário. Na hora, qualquer sessão aberta dele para de funcionar. Tudo que ele fez fica registrado na auditoria.

Resumindo

Um site, um cérebro, um arquivo. Login único, cada perfil vê o seu. Código novo publica sozinho; liberar é um clique. Custa menos de US$ 2 por mês.
